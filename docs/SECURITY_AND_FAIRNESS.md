# 安全与公平

## 身份与传输

- 玩家使用随机游客令牌恢复身份，数据库只保存令牌哈希。
- Cookie 使用 `HttpOnly`、`SameSite=Lax`；生产环境强制 `Secure`。
- Socket.IO 使用 30 秒有效的单次票据，服务端校验来源并忽略客户端提交的玩家身份。
- 房间码不是认证凭据；接口同时按来源地址和会话限流。
- 日志、指标和错误上报不得包含底牌、完整牌组、随机种子或恢复令牌。

## 可验证洗牌

每手开始时，服务端先提交随机秘密的哈希，活跃玩家再提交浏览器生成的 256 位随机贡献。服务端按座位排序贡献，通过 HKDF-SHA256 派生牌组密钥，再使用版本化 SHAKE256、拒绝采样和 Fisher-Yates 生成无偏牌组。

发牌前公布带盐牌组 Merkle Root。私有底牌只向所属玩家发送并附证明；公共牌公开证明。审计事件使用哈希链，房间关闭后的审计包公开重放材料和服务端签名，参与者可复原牌组并验证承诺、牌序和事件完整性。

## 公平边界

该机制能发现服务端在承诺后换牌或修改历史，但运行中的服务端仍可看到全部牌，也可能拒绝继续牌局或拒绝公开材料。它不能阻止串通、屏幕共享、终端被控制或玩家泄露底牌。娱乐筹码没有现金价值，不支持充值、转让、奖品或结算。

## 密钥与数据

`APP_SECRET_KEY` 用于派生审计加密与签名密钥，轮换会影响历史审计材料的解密和验证。轮换前必须保留受控旧密钥并验证恢复流程。房间关闭记录保留 7 天后清理；数据库备份使用独立口令，不能与应用密钥或数据库密码复用。
